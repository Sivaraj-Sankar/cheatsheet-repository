Every commit triggers automatic build → test → deploy pipeline.

2. CI/CD Pipeline (GitHub Actions)

name: CI-CD to Kubernetes on: push: branches: - main env: IMAGE_NAME: yourusername/myfastapi IMAGE_TAG: v1 jobs: build-and-deploy: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - name: Login Docker Hub uses: docker/login-action@v3 with: username: ${{ secrets.DOCKER_USERNAME }} password: ${{ secrets.DOCKER_PASSWORD }} - name: Build Image run: docker build -t $IMAGE_NAME:$IMAGE_TAG . - name: Push Image run: docker push $IMAGE_NAME:$IMAGE_TAG - name: Setup kubectl uses: azure/setup-kubectl@v4 - name: Deploy to Kubernetes run: | kubectl apply -f k8s/ kubectl set image deployment fastapi-deployment \ fastapi-container=$IMAGE_NAME:$IMAGE_TAG

3. Kubernetes Deployment (FastAPI)

apiVersion: apps/v1 kind: Deployment metadata: name: fastapi-deployment spec: replicas: 3 selector: matchLabels: app: fastapi template: metadata: labels: app: fastapi spec: containers: - name: fastapi-container image: yourusername/myfastapi:v1 ports: - containerPort: 8000
Deployment manages multiple Pods automatically.

4. Service (Internal Routing)

apiVersion: v1 kind: Service metadata: name: fastapi-service spec: selector: app: fastapi ports: - port: 80 targetPort: 8000 type: ClusterIP
Service → stable access point for Pods

5. Ingress (Public URL Access 🌐)

apiVersion: networking.k8s.io/v1 kind: Ingress metadata: name: fastapi-ingress spec: rules: - host: fastapi.local http: paths: - path: / pathType: Prefix backend: service: name: fastapi-service port: number: 80
https://fastapi.local → Ingress → Service → Pods

7. Docker Image Flow

docker build -t myfastapi:v1 . docker tag myfastapi:v1 yourusername/myfastapi:v1 docker push yourusername/myfastapi:v1
Code → Docker Image → Registry → Kubernetes pulls image

8. GitOps & Versioning Strategy

  • Git is source of truth
  • Every commit triggers CI/CD
  • Docker images are versioned (v1, v2, SHA tags)
  • Kubernetes automatically rolls updates
Commit → Build → Push → Deploy → Rollout

9. Key Concepts Summary

  • Pod → runs container
  • Service → stable networking
  • Deployment → manages Pods
  • Ingress → exposes to internet
  • GitHub Actions → CI/CD automation
