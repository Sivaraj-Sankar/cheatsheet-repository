Problem Statement

What problem is being solved?

🕒 Time-Intensive Manual Analysis

Energy sector professionals spend hours manually researching regulatory filings, market reports, M&A documents, HR policies, and deal data. Insights are delayed, costly, and inconsistent across analysts.

🗃️ Multi-Source Knowledge Silos

Critical information is scattered across AWS Bedrock Knowledge Bases, OpenSearch indices, Kendra, and external web sources — no unified interface to query all sources simultaneously.

📊 Decision Support at Scale

Deal screeners, compliance teams, and analysts need near-instant AI-assisted insights but existing systems lack the query decomposition and context reasoning to handle complex, multi-part questions.

📝 Lack of Traceable Citations

AI responses without source attribution are unusable in regulated industries. Users need answers backed by exact page, section, and paragraph citations from authoritative documents.

💡 The Core Solution

A hierarchical multi-agent AI platform that:

  • Decomposes complex queries into sub-tasks handled by specialized agents
  • Performs hybrid semantic + metadata-filtered retrieval across knowledge bases
  • Synthesizes multi-source answers with paragraph-level citations
  • Delivers results via real-time streaming (WebSocket + SSE) for perceived instant response
  • Supports configurable workflows per E·····s product and enterprise tier

Problem-Solving Challenges

Core technical and business problems that had to be solved

Problem Query Complexity & Decomposition

Real-world analyst queries are compound, ambiguous, and multi-intent. A single question like "What is the production profile and regulatory outlook for Operator X in the Permian?" requires multiple independent sub-queries across different knowledge domains.

Solution: Query Decomposer Agent breaks queries into sub-tasks. Each sub-task routes to a specialized agent (metadata extraction, categorical RAG, aggregative RAG). Results are synthesized by the Response Agent into a single coherent answer.

Problem Multi-Source Knowledge Retrieval

Answers must be grounded in authoritative sources — AWS Bedrock Knowledge Bases, OpenSearch indices, Kendra, and external web. No single retriever covers all sources. Incorrect source selection leads to hallucinated or irrelevant answers.

Solution: Three RAG variants — Categorical (category-filtered), Aggregative (cross-source merging), and C··········e (domain-specific filings). A fallback 3-tier retrieval ensures results even when strict filters yield nothing.

Problem Citation Accuracy in Regulated Industries

Energy sector and deal-making require legally defensible answers. Generic LLM responses without source attribution are unusable. Users need citations at the page, section, and paragraph level.

Solution: A structured citation model is embedded in chat_response.py. The RAG pipeline preserves document metadata (page, section, paragraph) through retrieval → reranking → response generation. Every claim in the answer is traceable.

Problem Latency vs. Quality Trade-off

AWS Bedrock Knowledge Base retrieval shows 45–300+ second latencies in production. Extended thinking (chain-of-thought) dramatically improves answer quality but multiplies cost and latency.

Solution: Streaming APIs (WebSocket + SSE) give users immediate partial responses, masking latency. Extended thinking is feature-toggled per workflow. Bedrock latency is instrumented with AWS Request IDs via OpenTelemetry for continuous optimization.

Problem Entity Resolution at Domain Scale

Energy domain queries reference companies by ticker symbols, legal names, abbreviated names, and legacy names. Incorrect entity resolution returns wrong data — a critical failure for deal screening and market intelligence.

Solution: EntityRegistry pattern with pluggable loaders. LLM-based extraction + fuzzy matching + DB lookups. Post-processing enriches resolved entities with authoritative metadata before passing to downstream agents.

Scalability Challenges

How the system is designed to grow and stay resilient

Scalability Stateful Multi-Turn Conversations at Scale

Multi-turn chat requires conversation history to be persisted across API requests and server instances. In-memory state breaks when requests hit different pods or servers restart.

Solution: Dual persistence — PostgreSQL via LangGraph's Postgres checkpointer stores full workflow state and conversation history. Redis/MemoryDB provides fast in-memory caching for active sessions. Flyway manages DB schema migrations.

Scalability Concurrent Streaming Responses

Supporting thousands of simultaneous users streaming long AI-generated responses would block synchronous threads and exhaust connection pools in a traditional architecture.

Solution: Fully async Python (async/await throughout). FastAPI handles both WebSocket and SSE streaming natively. AbstractWorkflowIterator yields token chunks as they arrive from the LLM, enabling true streaming with backpressure control.

Scalability Multi-Tenant Product Configuration

E·····s hosts multiple products (I·····t A·····t, D··l S·······r, HR A·······t) on one platform. Each product needs different agents, knowledge bases, feature sets, and models without a separate deployment.

Solution: ProductRegistry + WorkflowRegistry pattern. Feature toggles are per-product and per-workflow. Agent configuration supports inheritance and fallback. A single API deployment serves all products through runtime routing.

Scalability Observability at Production Scale

Diagnosing latency issues, cost spikes, and hallucinations in production requires distributed tracing across agents, models, and knowledge bases — standard logging is insufficient.

Solution: Full observability stack — OpenTelemetry for distributed tracing, Prometheus for metrics, Grafana + Tempo for visualization, and LangSmith for LLM-specific debugging and evaluation. AWS Request IDs are captured for Bedrock calls.

Scalability Long-Running Workflow Recovery

Complex agentic workflows (deal screening, iterative research) can run for minutes. If a worker crashes mid-workflow, all partial work is lost and the user must restart from scratch.

Solution: LangGraph checkpoint-based recovery. Each workflow node persists its state to PostgreSQL before advancing. On failure, the workflow resumes from the last checkpoint — transparent to the user.

Scalability AWS Bedrock Cost at Scale

At enterprise scale, Bedrock API calls (model inference + knowledge base retrieval) become the dominant cost driver. Naive implementations call the API on every request, even for identical queries.

Solution: Vector store caching layer in response_augmentation/caching/ deduplicates identical KB queries. Token usage tracked per agent via TokenUsageModel. Quota enforcement prevents runaway spend. Cross-account inference profiles optimize pricing.

Agentic Architecture Challenges

Challenges specific to building and orchestrating multi-agent AI systems

Agentic Hierarchical Agent Orchestration

Coordinating 16+ specialized agents — each with its own LLM, tools, and state — without race conditions, duplicate work, or conflicting results is fundamentally hard. Simple sequential chains can't leverage parallelism.

Solution: LangGraph as the orchestration backbone. Workflows model agent coordination as typed directed graphs with conditional edges. Linear, conditional, and parallel workflow patterns all supported. AbstractChatbotWorkflow provides a reusable base.

Agentic Structured Output Reliability

LLMs don't reliably produce valid JSON or schema-compliant outputs on every call — especially for complex nested structures like citations, entity lists, or metadata objects. Hallucinated or malformed outputs break downstream agents.

Solution: BaseStructuredOutputReactAgent and BaseStructuredOutputStrandsAgent implement automatic retry on schema validation failure. On repeated failure, the system falls back to a stronger model. The Strands framework adds metric tracking and production-safe error handling.

Agentic Workflow Routing Intelligence

A single chat endpoint must correctly route queries to 6 different workflow types (RAG, D··l S·······r, Iterative Research, Multimodal, Summary, HR G·····l). Incorrect routing sends a query to the wrong agent graph with wrong knowledge bases.

Solution: Workflow Identifier Agent classifies incoming queries and routes to the correct workflow. Product context, feature flags, and conversation history all inform routing decisions. The WorkflowRegistry maintains the routing map.

Agentic Agent State Consistency

Agents in a graph share a mutable WorkflowState dictionary. Without careful design, agents can overwrite each other's results, lose context from earlier steps, or see stale intermediate state.

Solution: WorkflowState is a TypedDict with explicit field ownership per agent. LangGraph's reducer pattern handles merge semantics. The state includes messages, retrieved context, extracted entities, and intermediate results — each agent reads only what it needs and writes only its own output keys.

Agentic Extended Thinking & Chain-of-Thought

For complex deal screening and research queries, shallow one-shot LLM responses miss nuance. But enabling extended thinking (Claude's chain-of-thought) on every query is prohibitively expensive and slow.

Solution: Extended thinking is a feature toggle per workflow. The Iterative Research and D··l S·······r workflows enable it; simpler FAQ-style queries don't. Claude Sonnet 4 with extended thinking is used only where the quality gain justifies the cost.

Agentic MCP & Tool Extensibility

As the platform grows, adding new tools (web search, calculators, external APIs) to agents shouldn't require rewriting agent logic or redeploying the entire platform.

Solution: Model Context Protocol (MCP) integration via FastMCP. Tools are registered as MCP servers and discovered at runtime. The BaseReactAgent supports dynamic tool loading, making the platform extensible without agent code changes.
