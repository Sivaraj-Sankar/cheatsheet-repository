2. Blue-Green Deployment (Zero Downtime) 🟦🟩

Blue (v1 - Live)
← Traffic
Load Balancer
→
Green (v2 - New)
Switch traffic from Blue → Green after validation. Instant rollback = switch back to Blue.
kubectl apply -f green-deployment.yaml kubectl patch service myapp -p '{"spec":{"selector":{"version":"green"}}}'

3. Canary Deployment 🐤

90% v1
+
10% v2
Gradually route traffic to new version. If stable → increase traffic to v2.
apiVersion: networking.k8s.io/v1 kind: Ingress metadata: name: canary-ingress annotations: nginx.ingress.kubernetes.io/canary: "true" nginx.ingress.kubernetes.io/canary-weight: "10"

4. Helm (Industry Standard) ⚙️

Helm = Package Manager for Kubernetes
helm create fastapi-chart helm install fastapi ./fastapi-chart helm upgrade fastapi ./fastapi-chart

Why Helm?

  • Templated YAML (no duplication)
  • Easy environment management (dev/stage/prod)
  • Versioned releases

5. Debugging CI/CD Failures 🔍

Common Issues

  • ImagePullBackOff → wrong image name or registry issue
  • CrashLoopBackOff → app crashing inside container
  • Pending Pods → no available resources

Useful Commands

kubectl get pods kubectl describe pod kubectl logs kubectl get events

CI/CD Debugging (GitHub Actions)

# Check workflow logs in GitHub Actions tab # Common failures: - Docker login failed - Missing secrets - Wrong kubeconfig

6. FastAPI Deployment Example

apiVersion: apps/v1 kind: Deployment metadata: name: fastapi-deployment spec: replicas: 3 selector: matchLabels: app: fastapi template: metadata: labels: app: fastapi spec: containers: - name: fastapi image: yourusername/myfastapi:v1 ports: - containerPort: 8000

7. Service (Internal Routing)

apiVersion: v1 kind: Service metadata: name: fastapi-service spec: selector: app: fastapi ports: - port: 80 targetPort: 8000 type: ClusterIP

8. Ingress (Public Access 🌐)
